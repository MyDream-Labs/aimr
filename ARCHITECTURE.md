# Архитектура AIMR

Рабочие договорённости и открытые вопросы. Обновляем кратко по мере обсуждения; это направление развития, а не перечень готовых возможностей.

## Модель

- **IDE — фундамент:** файлы, окна, команды, настройки, агент и инфраструктура расширений.
- **Расширения — строительные блоки:** инструменты, интерфейсы, подключения к данным и выполнение сценариев.
- **Папка проекта — персональный «дом»:** данные, скрипты, воркфлоу, настройки и связи между блоками.
- Агент помогает собрать и развивать рабочую среду. Созданный инструмент должен сохраняться и работать после закрытия чата и перезапуска AIMR.

## Принципы

- Стандартизируем стыки между блоками; устройство проекта оставляем свободным.
- У блока понятны назначение, входы, выходы и способ запуска. Агент должен уметь это обнаружить.
- Переиспользуем команды расширений, штатные задачи, обычные скрипты и существующие форматы данных. Схемы добавляем по необходимости.
- Пути внутри проекта — относительные. Пользовательские данные сохраняем отдельно от устанавливаемого кода расширений; секреты — вне переносимых файлов проекта.
- Конкретный инструмент может состоять из файлов проекта и готовых блоков. Отдельное расширение нужно, когда оно добавляет необходимую возможность.
- KISS, YAGNI, минимум owned-кода. Общие соглашения выделяем из работающих примеров.

Пример: CSV продаж → скрипт расчёта → JSON показателей → панель графиков. Проверка совместимости: можно заменить блок, сохранив согласованные входы и выходы.

## Следующие вопросы

- Собрать два рабочих примера из общих блоков и определить минимальные соглашения для их соединения.
- Решить, как описывать состав «дома», находить и открывать его инструменты, переносить и восстанавливать среду.
